# Platform website SEO

The public MetoHub website now uses `MarketingSeo` and `landing.partials.seo` for page-specific titles and descriptions, canonical URLs, Open Graph/Twitter previews, icons, robots metadata and JSON-LD. Blog articles retain their own titles, descriptions and cover images. Missing covers use the bundled sharing artwork.

Canonical URLs use `APP_URL` and omit tracking and signup query parameters. The confirmed production domain is `https://metohub.cloud`. Use that value in the production .env; keep local development on localhost. Redirect the retired beta domain to the production domain while preserving paths and query parameters.

Structured data describes the Organization, WebSite and current WebPage, with the provided public email, phone and Kochi location. It includes no client ratings, fictional endorsements or invented business results. Sample seller stories are marked `data-nosnippet` so their illustrative text is excluded from search snippets where supported.

The share image is `public/images/landing/social-card.png` (1200×630). Its editable SVG and optional Chrome render script are included. Deploy the PNG; browsers and social crawlers do not need the render script or an npm build.

The platform sitemap includes the homepage, Features, Pricing, Themes, About, Contact, Blogs, Privacy, Terms, Refund/Cancellation and Security. The existing `/sitemap.xml` index references `/sitemap-platform.xml` and eligible tenant sitemaps. When `BLOG_API_KEY` is configured, the index also references `/sitemap-blogs.xml`. This dedicated sitemap loads individual article URLs from the same external feed as the blog pages, using the existing five-minute cache. The root and static-page sitemaps do not call the feed. Article URLs use this platform’s `APP_URL` and `/blogs/{id}`, not the external blog host. Duplicate IDs are omitted. Valid, non-future `updated_at` values become `lastmod`; missing or invalid dates are omitted rather than fabricated.

## Server configuration

```dotenv
APP_URL=https://metohub.cloud
SEARCH_INDEXABLE=true
PLATFORM_GOOGLE_SITE_VERIFICATION=
```

Set `SEARCH_INDEXABLE=false` for environments you do not want indexed, including a private beta/staging environment. It controls robots.txt, page metadata and response headers. This release does not change the server's actual .env file or turn indexing on automatically.

If using Google's HTML-tag verification method, place only the token from the verification tag in `PLATFORM_GOOGLE_SITE_VERIFICATION`. This applies to the platform website, separate from merchant integrations. Alternatively use Google's DNS verification method.

After deployment:

```sh
php artisan optimize:clear
php artisan config:cache
php artisan view:cache
```

No new Composer/npm dependencies or database migration are required. Include the new service, SEO partial, artwork and configuration when deploying.

Verify the domain in Google Search Console and submit `https://metohub.cloud/sitemap.xml`. Inspect the homepage and important pages there after publishing. Confirm production serves a successful response, a correct canonical and an accessible sharing image. This local implementation does not establish that Google has crawled or indexed the site, and it does not guarantee rankings.

Private routes, signup query variants, previews and error responses receive `X-Robots-Tag: noindex, nofollow`. A blanket staging switch takes precedence. Authentication still protects private information; robots directives are not access control.

## Dynamic robots and blog sitemap

These endpoints are generated by Laravel, not uploaded XML/text files:

- `/robots.txt`: crawler policy plus the canonical platform sitemap URL (or the tenant host’s sitemap on a connected custom domain).
- `/sitemap.xml`: index of the platform, configured blog and eligible merchant sitemaps.
- `/sitemap-platform.xml`: public platform pages and policies.
- `/sitemap-blogs.xml`: article URLs returned by the configured public project feed.

The obsolete tracked `public/sitemap.xml` has been removed. It referenced an old domain and would have bypassed Laravel on Apache/Nginx. Deploy that deletion as well as the new routes and code. Do not leave or add physical `public/sitemap.xml` or `public/robots.txt` files on the server, because static-file serving can override the dynamic endpoints. Normal Laravel web-server front-controller routing is required.

New or removed posts appear after the existing five-minute feed cache refresh. The sitemap and public blog listing share this cache; no database seeding or manual sitemap rebuild is needed. It represents articles returned by the project's public API, so unpublished/private entries must not be returned by that upstream public feed.

If the feed fails, the last successful response can be served for up to a day. Without a usable saved feed, the blog sitemap returns HTTP 503 with `Retry-After: 3600`; it does not falsely report an empty publication list. A genuinely successful empty feed produces valid empty sitemap XML. The platform sitemap and robots.txt remain independent of this outage. Disabled global indexing blocks the blog sitemap before any API request, and tenant custom domains cannot expose the platform blog sitemap.

Tests cover shared caching, duplicate/invalid IDs, XML parsing, actual update dates, refreshes adding/removing posts, successful empty responses, cached outage fallback, retryable outages and staging/missing-key behavior. The existence of a sitemap does not establish that Google has fetched or indexed the articles.

## Additional code-side SEO pass

- Blog pages now include `BlogPosting` and visible breadcrumb navigation with matching `BreadcrumbList` data. Headline, author, cover and dates come from the normalized feed. Missing or future dates are omitted; a modified date preceding publication is not invented or substituted. The fallback editorial author points to the existing MetoHub Organization. JSON remains safely escaped.
- Blog covers reserve space and receive priority loading. Author, related-post and content images use lazy loading/async decoding; sanitized HTML retains only sensible numeric width/height pairs. This reduces avoidable loading/layout work but is not a measured live performance score.
- Blog articles link to theme browsing, plan comparison and the actual trial signup URL. Shared footer links expose Features, Themes and Pricing. Social-sharing actions use the canonical platform article URL.
- `/home` and `/home1` permanently redirect to the main landing page. `/templates` permanently redirects to `/themes`. Leading-zero article IDs redirect to their normalized numeric URL. Query parameters are preserved; canonical metadata still omits campaign tracking. Beta-domain redirects remain a hosting task for the owner.
- Standalone public pages have one main H1; reusable sections retain H2 when embedded. The inner-page layout identifies the main content region and no longer requests a duplicate font stylesheet.
- About-page unverified store/order counts, uptime SLA and round-the-clock support statistics were replaced with configured theme count, trial length, starting price and branding options. Sample review personas remain explicitly labelled as requested; genuine client feedback still needs to be supplied by the owner.

Article and breadcrumb references: [Google Article documentation](https://developers.google.com/search/docs/appearance/structured-data/article), [Google Breadcrumb documentation](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb).

Owner tasks remain deployment, correct production environment/DNS/redirects, Search Console verification and submission, useful original articles and approved real client feedback, followed by live PageSpeed and indexing monitoring. These require production/account access or source material outside this repository.
